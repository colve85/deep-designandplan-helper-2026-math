# 깊이 있는 수업·평가 설계 도우미 — 수학 과목 확장판

「2026 깊이있는 수업 평가 설계 연수생용 워크북」의 **목표 → 평가 증거 → 학습 경험** 설계 흐름을 적용한 교사용 웹앱입니다. 결과를 JSON과 한글 문서(.hwpx)로 내려받습니다. 기존 v2.3.0을 바탕으로 만든 **v2.7.0 별도 수정본**이며 원 제작자와 MIT 라이선스를 유지합니다.

## 교수학습 및 평가 운영 계획 (2.7.0)

상단 **교수학습·평가 운영 계획**에서 과목별·학기별 계획을 작성합니다. **현재 단원 설계 추가**를 누르면 선택한 단원의 수업 및 평가 초안을 가져옵니다. 같은 과목의 여러 단원을 한 계획에 모을 수 있으며, 각 표의 행을 추가·삭제·이동하고 내용을 수정할 수 있습니다.

학년도·학기는 직접 입력합니다. **시기·시수·누계는 기본값이 빈칸이며 자동 계산하지 않습니다.** 평가비율·배점·학교 규정과 성취수준도 학교에서 확정하여 입력합니다. **다른 학기용 복사**는 수업 내용을 유지하고 학년도·학기·일정·시수·누계를 비웁니다.

**운영 계획 한글 저장**으로 실제 HWPX 파일을 받습니다. 한글에서 열고 편집할 수 있는 형식이며, 기존 HWP 확장자로 이름만 바꾼 파일이 아닙니다. JSON 저장·불러오기도 지원합니다. [운영 계획 사용 안내](docs/operation-plan.md)를 참고하세요.

## 변경 사항

- **21개 과목군 · 74개 공식 영역 · 194개 공식 내용요소**를 별책8·별책20 원문과 연결했습니다.
- 기존 **53개 탐구 단원 · 212개 수업 소재 카드**도 유지하여 공식 대조와 실제 수업 예시를 함께 제공합니다.
- 기존 공통수학1·2의 18개 단원·72개 카드를 유지하고 13개 과목의 35개 탐구 단원·140개 카드를 추가했습니다.
- 기존 추가 단원마다 수치 자료, 핵심 질문, 평가요소, 수행과제, 3수준 루브릭, 4차시 흐름, 오개념 발문, 교사용 예상 결과, 조건 변경 전이 과제를 제공합니다.
- 공식 대조 단원에는 교육과정 원문의 핵심 아이디어·지식·이해·과정·기능·가치·태도와 관련 성취기준을 연결하고, 공식 내용요소별 카드를 제공합니다.
- 성취기준 원문을 단원별로 수정하면 AI 프롬프트·미리보기·한글 문서에 반영됩니다. JSON에도 수정 내용이 보존됩니다.
- 단원별 작성 내용을 보관·복원하여 과목을 바꿀 때 설계 내용이 섞이지 않도록 했습니다.
- 워크북의 3수준 루브릭과 기존 앱의 4수준 루브릭을 모두 점검합니다.

## 원문과 예시의 구분

기존 수업 예시의 성취기준은 원 저장소 자료 또는 교사 재구성 목표입니다. 공식 대조 단원은 별책8·별책20에서 추출한 공식 내용요소와 성취기준을 연결해 표시합니다. 학교의 실제 수업 범위에 맞는 원문은 왼쪽 **성취기준 원문 입력·수정**에 `코드 | 원문` 형식으로 확정 입력할 수 있습니다.

### 워크북 확장 설계 양식

붙여넣은 연수생용 워크북의 구조를 0~3단계에 확장했습니다. 교육과정 핵심 아이디어 원문, 성취기준 해설·적용 시 고려 사항, 지식·이해·과정·기능·가치·태도, 재구성 단원 제목과 개념 렌즈, 단원 그물·스트랜드, 사실적·개념적·논쟁적 질문, GRASPS, 이해의 6가지 증거, 평가요소별 3수준 채점 기준, 차시별 학습 경험·평가·피드백·성찰을 작성할 수 있습니다. **모든 단계에 예시 채우기**를 누르면 공식 내용요소와 기존 단원 자료를 바탕으로 이 확장란도 함께 채워집니다.

공식 영역과 내용요소는 교육과정 원문 기준이며, 뒤에 붙은 제목은 핵심 아이디어와 주요 수행을 암시하는 수업 설계 제목입니다. 각 차시는 탐구 카드 예시이며 개념 도입과 연습에 필요한 전체 시수와 다릅니다.

신규 수치 자료는 가상·모형 자료입니다. 워크북의 구조를 적용하여 새로 작성한 수학 예시이며 워크북 사례의 전사가 아닙니다. 루브릭은 공식 성적등급과 자동 대응하지 않습니다. [워크북 반영 안내](docs/workbook-mapping.md)를 참고하세요.

## 사용 순서

1. 과목 → 영역 → 탐구 단원을 선택합니다.
2. 성취기준 원문과 대상·차시·학급 상황을 입력합니다.
3. **모든 단계에 예시 채우기**로 초안을 불러와 수정합니다.
4. 목표·핵심 질문을 정하고 평가요소·증거·수행과제를 먼저 설계합니다.
5. 3단계 소재 카드의 목표·증거를 확인하여 차시표에 넣습니다. 최종 수행에 필요한 적용 → 탐색 → 발견 활동을 역순으로 검토합니다.
6. 설계 점검·미리보기를 확인하고 JSON 또는 한글 문서를 내려받습니다.

카드에는 교사용 예상 결과도 포함됩니다. 학생용으로 배포할 때는 정답·교사용 안내를 편집하세요. 설계 점검 점수는 문구·구조 점검이며 수학적 정확성이나 수업의 질을 인증하지 않습니다.

## GitHub 업로드와 실행

압축을 푼 뒤 **이 README가 있는 폴더의 내용 전체**를 저장소 루트에 올리세요. `src`, `api`, `lib`, `tools`, `docs`, `public`, `.github`와 루트 설정 파일이 모두 필요합니다. ZIP 자체만 올리면 소스로 배포되지 않습니다. 점으로 시작하는 파일도 포함하세요.

기존 저장소에 반영한다면 새 `UnitsExtendedMath.gs`, `UnitsOfficialMath.gs`뿐 아니라 `OperationPlan.gs`, `OperationScript.html`, `Hwpx.gs`, `Code.gs`, `Api.gs`, `Script.html`, `Stages.gs`, `Index.html`, `lib/gas-runtime.js`, 문서·검증 파일도 함께 반영합니다.

이 앱은 서버 API가 필요하므로 **현재 구성 그대로 GitHub Pages에서는 실행되지 않습니다.** GitHub에 소스를 보관하고 Vercel 또는 Google Apps Script에서 실행합니다.

Node.js 18 이상에서 외부 npm 패키지 설치 없이 확인할 수 있습니다.

```bash
npm run verify
npm run dev
```

`http://localhost:8080`으로 접속합니다. `Index.html`을 파일로 직접 열면 서버 호출이 작동하지 않습니다.

**Vercel:** GitHub 저장소를 연결하고 Framework Preset은 Other로 선택합니다. 저장소의 `vercel.json`을 사용합니다. [배포 안내](docs/deployment.md)를 참고하세요.

**Apps Script:** `src`의 `.gs` 파일 **11개**, `.html` 파일 **4개**를 모두 추가합니다. 새 `UnitsExtendedMath.gs`와 `UnitsOfficialMath.gs`도 필요합니다. clasp 사용 시 `.clasp.json.example`을 `.clasp.json`으로 복사하고 본인 scriptId를 입력합니다. 실제 연결 설정은 업로드하지 않습니다.

AI 없이 예시 편집·소재 불러오기·문서 출력을 사용할 수 있습니다. 자동 생성은 본인 Gemini 키가 필요하며 키가 없으면 프롬프트 복사·결과 붙여넣기를 사용합니다. Node 배포는 키를 브라우저에 보관하고 요청 시 서버를 거쳐 Gemini로 전달합니다.

### 2.6.3 예시 채우기 수정

기존 작성 내용을 보존하며 빈칸을 보완하려면 **모든 단계의 빈칸만 예시 채우기**를 사용합니다. 이전의 잘못된 예시까지 교체하려면 **모든 단계에 예시 채우기**를 사용합니다. 해당 동작은 네 단계의 작성 내용을 예시로 교체하므로 직접 작성한 내용은 먼저 JSON으로 내보낼 수 있습니다. 단계별 예시 넣기는 선택한 단계만 바꿉니다. 앱 왼쪽 제작 표기의 버전 2.7.0으로 적용 여부를 확인할 수 있습니다.

확장 항목은 단원의 기존 자료에서 구성한 교사 설계 제안입니다. 교육과정 해설 원문이 별도 수록되지 않은 곳은 확인 필요로 표시하며, 과정·기능이나 지원 전략을 공식 해설로 제시하지 않습니다.
